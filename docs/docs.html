NeoAdmin Overview

NeoAdmin is a reusable administration dashboard template built with Bootstrap 5.3, TypeScript, SCSS, Pug, and Vite.

Use it as a complete static site, or reuse its compiled theme assets and semantic page examples in an existing application. The active runtime is framework-free TypeScript with Bootstrap and browser APIs; React, Vue, and Angular components are not part of this release.

Open the DashboardView the Technical Overview

Quick Start

Clone the repository, install its development dependencies, then start the local Vite server.

git clone https://github.com/cesarobenites/NeoAdmin.git
cd NeoAdmin
npm install
npm run dev

The local server lets you preview the Pug examples while editing their source. Build the static site when the changes are ready.

npm run build
npm run preview

The production build type-checks TypeScript, bundles Vite assets, compiles the local icon catalog, and renders the top-level Pug pages into docs/.

Build System

Use these commands from the repository root to develop, generate, and preview the distributable site.

Command Result
npm run dev Starts the Vite development server for the Pug examples and theme source.
npm run build Type-checks TypeScript and creates the complete static website under docs/.
npm run preview Serves the generated website locally so the production output can be reviewed.
npm run build:vue Builds the ES module profile with automatic initialization disabled for a host application.

Publish the contents of docs/ with GitHub Pages. The build:vue profile remains a framework-free TypeScript module and does not generate Vue components.

Use NeoAdmin as Your Application

Choose this workflow when you want the NeoAdmin dashboard itself to be the application. Keep the repository, edit its source, and deploy the generated site.

  1. Edit page examples and shared layout in src/pug/.
  2. Customize colors, typography, spacing, and surfaces in src/scss/neoadmin/_vars.scss.
  3. Add shared components under src/scss/neoadmin/component/ and page-specific styles under src/scss/neoadmin/pages/.
  4. Add interactions and page integrations in src/ts/.
  5. Run npm run build and deploy the generated docs/ directory with GitHub Pages or another static host.

Treat src/ as the editable source and docs/ as compiled output. Do not make manual changes to generated pages.

Use NeoAdmin as a Template in Another Project

Use NeoAdmin as a complete static dashboard by customizing this repository and deploying docs/. To use its design in an existing React, Vue, or Angular application, build NeoAdmin and copy the assets and examples that the host project needs. NeoAdmin is a starter template and theme, not a package of framework components.

  1. Run npm install and npm run build in the NeoAdmin repository.
  2. Copy docs/assets/css/neoadmin.css into the host application's public assets. Copy neoadmin-icons.css and its WOFF2 font only when using Bootstrap Icons; add only the required images and optional integrations.
  3. Use generated docs/*.html or source examples in src/pug/ as references. Convert the needed structure into React JSX/TSX, Vue templates, or Angular templates, then adjust asset paths.
  4. Load the theme stylesheet once. Let the host framework handle routing, rendering, and component lifecycle; include Bootstrap JavaScript only for components that require it.
  5. Connect the needed data-neoadmin-* hooks and neoadmin:* DOM events to host interactions. Do not start the page-wide runtime independently in every routed component.

React, Vue, and Angular components, adapters, and project generators are not included. npm run build:vue creates a framework-free ES module with automatic initialization disabled; it does not generate Vue components.

Read Framework Support for the implementation boundary and AI Agent Guide for using NeoAdmin skills in another repository.

Theme, Fonts, and Icons

The Sass palette and shared layout tokens are defined in src/scss/neoadmin/_vars.scss. The built theme uses Bootstrap CSS variables for component surfaces and supports the existing light and dark modes.

The browser toolbar theme color follows the active NeoAdmin theme automatically. Light mode uses the compiled $primary token; dark mode uses the dark header surface. TypeScript reads --neoadmin-browser-theme-color from the compiled theme and updates the theme-color meta tag on page startup and when Light or Dark is selected. Change the Sass tokens and run npm run build; no separate Pug color value is needed. Browser support and presentation vary by browser and device.

In the standalone template, Theme Mode on page-settings.html saves a manual Light or Dark choice in localStorage under the exact key neoadmin-theme. The accepted values are light and dark. System mode removes the key, then TypeScript follows prefers-color-scheme and responds to system changes.

localStorage.getItem('neoadmin-theme')

To force Dark mode from the browser console, save the value and reload:

localStorage.setItem('neoadmin-theme', 'dark'); location.reload()

To return to System mode, clear the override and reload:

localStorage.removeItem('neoadmin-theme'); location.reload()

To change where the preference is stored, edit getStoredTheme() and setTheme() in src/ts/neoadmin.ts. getStoredTheme() reads the preference; setTheme() saves Light or Dark and removes the override for System. Keep applyTheme() to synchronize the page and the browser toolbar color. Rebuild with npm run build after changing the TypeScript source. A host application can replace this storage with its cookie, server, or account preference.

Secondary buttons use the Bootstrap secondary palette with white text for a clear contrast against primary actions.

Bootstrap Icons are included as a separate local catalog at docs/assets/css/neoadmin-icons.css with its local WOFF2 font. The theme does not need a remote icon CDN. Bootstrap form controls use the system font stack.

Keep icon styles linked once through the shared layout. Prefer available Bootstrap utilities and project tokens before introducing additional styles or dependencies.

Optional Components and Loading

Page integrations load only when the matching example requests them. DataTables, responsive tables, charts, Tom Select, IMask, and Flatpickr are split into optional imports so unrelated pages can avoid their code.

  • Data Tables demonstrates responsive tables, state, density, search, and CSV export.
  • Date & Time demonstrates date, date-time, range, and month/year inputs with Flatpickr.
  • Bootstrap Icons remain available from the separate stylesheet when an example needs an icon.
  • UI Cards demonstrates Bootstrap's CSS-only skeleton placeholders; they need no JavaScript or framework.

    • The shared admin layout includes an asynchronous modal skeleton. Trigger it with data-neoadmin-modal="load" and data-neoadmin-url="..."; the TypeScript runtime displays placeholders while fetch() loads the content, then replaces them with the response.

    <button type="button" data-neoadmin-modal="load" data-neoadmin-url="form-fragment.html" data-neoadmin-title="Edit profile">
  Edit profile
</button>

    The landing page also demonstrates a full-page startup loader in src/pug/index.pug; the TypeScript runtime removes it after initialization. Use this for a brief page startup state, and use skeletons for content regions waiting on asynchronous data.

    Use .placeholder-glow or .placeholder-wave with .placeholder elements for content previews. Set aria-busy="true" while loading and replace the skeleton with the loaded content when the request completes. See UI Cards and the asynchronous modal in the shared layout.

    NeoAdmin TypeScript API

    Page controls use semantic HTML and data-neoadmin-* attributes. The same markup can be adapted into a framework template without inline event handlers.

    Notifications
    NeoAdmin.notify('Update successful!', 'success');

    The alert appears at the top of the page and closes automatically after five seconds.

    Confirmation
    NeoAdmin.getInstance().confirm({ title: 'Good Job!', message: 'Operation completed.', onConfirm: () => {} });

    The command palette opens with Ctrl + K or Cmd + K. On mobile, open Quick Search from the footer navigation. It supports page navigation and quick theme actions.
