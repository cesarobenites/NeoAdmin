AI Agent Guide

Use NeoAdmin rules and skills with the tools you already use

  • Documentation
  • AI Agent Guide

The Three Parts of Agent Guidance

NeoAdmin keeps agent guidance separate from the application UI. The project root contains small tool entry points; the `.agents/` directory contains the reusable rules, technical context, and skills.

Part Purpose NeoAdmin location
Rules Constraints that apply across tasks and limit unnecessary changes .agents/rules/project-standards.md
Context Technical facts the agent should check before changing architecture or build behavior .agents/context/
Skills Focused procedures loaded for a matching task, such as Pug or Sass work .agents/skills/neo-admin-skill-*/SKILL.md

Rules are not a task checklist and skills are not installed application code. The agent uses a skill to work through a requested task while the rules constrain how it changes this repository.

Start an Agent Session in NeoAdmin

  1. Open the repository root as the workspace so the root instruction file and `.agents/` directory are available.
  2. Describe the requested outcome and the page, component, or behavior involved.
  3. Ask the agent to use the matching skill when the task is specialized, for example neo-admin-skill-pug for a Pug page or neo-admin-skill-scss for a theme change.
  4. Review the source changes and the generated page in docs/ after the build.

Keep requests specific. For example: “Use neo-admin-skill-bootstrap to align the account actions at Bootstrap’s 768px breakpoint. Preserve the desktop header and the optional bottom navigation, then validate both sides of the breakpoint.”

Use the Agent in Your Preferred Tool

Keep NeoAdmin's project rules and task workflows in their canonical files. Open the repository root, make the tool aware of AGENTS.md, and ask it to follow the relevant .agents/skills/*/SKILL.md. If the tool requires a native instruction file, use that file as a short pointer to these sources instead of copying their full contents.

Tool Practical setup
Claude Code Open the repository as the working directory. Use a concise root CLAUDE.md pointer to AGENTS.md and the relevant NeoAdmin skill when Claude Code needs native project instructions.
OpenAI Codex Open the repository as the project or workspace. It can use the root AGENTS.md entry point and the linked rules and skills.
Google Antigravity Open the repository as the workspace and use its project rules and skills. Invoke a skill by name when supported, or ask the agent to read its SKILL.md.
Gemini CLI Start the CLI in the repository and provide AGENTS.md as project context. Ask it to read the relevant skill before specialized work.
GitHub Copilot and other tools Configure the tool's native project-instruction mechanism with a short pointer to AGENTS.md, then refer to the matching NeoAdmin skill as needed.

Tool features and instruction discovery differ and can change by version. Check each tool's current project-instruction settings; keep NeoAdmin's actual standards in one canonical place.

Use NeoAdmin Skills in Another Repository

Use this when another application needs NeoAdmin's visual patterns but should keep its own source, routing, and architecture.

  1. Copy only the relevant skill folders from NeoAdmin's .agents/skills/ into the host repository's .agents/skills/ directory.
  2. Keep the host repository's own rules and architecture in its native project instructions.
  3. Ask its agent to use a copied NeoAdmin skill for the specific task.
  4. Copy and adapt only the required theme assets and semantic Pug examples for the host framework.

Do not copy NeoAdmin's complete agent rules or repository context into an unrelated application. The skills describe NeoAdmin conventions; the host repository still owns its architecture and lifecycle.

Build the Application or Reuse the Theme

Standalone NeoAdmin site

Clone the repository, run npm install and npm run dev, customize the source under src/, then run npm run build. Deploy the generated docs/ directory.

Existing React, Vue, or Angular application

Build NeoAdmin, copy docs/assets/css/neoadmin.css and only the needed icons, fonts, images, and optional integrations into the host project's public assets. Adapt the generated HTML or Pug examples into JSX/TSX, Vue templates, or Angular templates, and update asset paths. Load the theme once; let the host application own routing and component lifecycle.

React, Vue, and Angular components, adapters, and project generators are not included. npm run build:vue only emits a framework-free ES module with automatic initialization disabled; it does not provide Vue components.
